## 1. 项目概述

### 1.1 项目背景

本项目是"基于终端波形数据的电能质量 AI 应用"的嵌入式软件实现，核心目标是：

- **实时采集**：通过 HT7627S 高精度计量芯片，以 12.8 kHz 采样率同步采集 7 通道（3 相电压 + 3 相电流 + 零序）波形数据。
- **指标计算**：实时计算电压偏差、THD、三相不平衡度、频率偏差、变压器/线路负载率等 12 项电能质量指标。
- **事件检测**：基于国标限值，检测电压暂降/暂升、谐波超标、不平衡、过载等异常事件。
- **AI 推理**：部署孤立森林（iForest）、自编码器（AE）、1D-CNN 三类模型，实现异常检测与事件分类。
- **场景识别**：自动识别 S1~S5 五类典型场景（基准负荷、充电桩、分布式光伏、光充耦合、极端工况），并给出治理建议。
- **数据上报**：通过 MQTT 将指标、事件、AI 结果上报云端；本地持久化存储波形与日志。

#### 3.2.1 `pq_common.h` —— 工程基石

所有 `.c` 文件都应首先包含此头文件。它定义了：

- **关键常量**：
  - `PQ_SAMPLE_RATE_12800 = 12800`：采样率 Hz
  - `PQ_POINTS_PER_CYCLE_12800 = 256`：每周期采样点数
  - `PQ_N_CHANNELS = 7`：3 相电压 + 3 相电流 + 零序
  - `PQ_MAX_HARMONIC_ORDER = 31`：支持到 31 次谐波
- **平台宏**：`PLATFORM_WINDOWS` / `PLATFORM_EMBEDDED`
- **调试宏**：`PQ_LOGI` / `PQ_LOGW` / `PQ_LOGE`，自动打印文件名和行号

```c
#include "pq_common.h"

PQ_LOGI("System started, sample_rate=%u", PQ_SAMPLE_RATE_12800);
// 输出: [PQ][INFO] main.c:42 System started, sample_rate=12800
```

#### 3.2.2 `pq_hal.h` —— 硬件抽象层接口

定义了与 HT7627S 交互的全部数据结构，**仿真与真实硬件共用同一套结构体**。

```c
/* HT7627S 配置 */
typedef struct {
    uint32_t sample_rate;      /* 12800 或 25600 */
    uint16_t pts_per_cycle;    /* 256 或 512 */
    uint16_t n_channels;       /* 7 */
} ht7627s_cfg_t;

/* HT7627S 计算结果寄存器 */
typedef struct {
    float rms[PQ_N_CHANNELS];              /* 7 通道 RMS */
    float thd_v;                           /* 电压 THD % */
    float thd_i;                           /* 电流 THD % */
    float harmonics[PQ_MAX_HARMONIC_ORDER]; /* 2~31 次谐波含有率 */
    float active_power;                    /* 有功功率 kW */
    float reactive_power;                  /* 无功功率 kvar */
    float apparent_power;                  /* 视在功率 kVA */
    float power_factor;                    /* 功率因数 */
    float frequency;                       /* 频率 Hz */
    float phase_angle[PQ_N_CHANNELS];      /* 相位角 */
} ht7627s_regs_t;

/* HT7627S 原始波形 */
typedef struct {
    float samples[PQ_N_CHANNELS][PQ_POINTS_PER_CYCLE_25600];
    uint16_t valid_samples;
    uint32_t cycle_id;
    uint64_t timestamp_us;
} ht7627s_wave_t;
```

### 3.3 仿真层（sim/）

#### 3.3.1 `hal_sim.c` —— HT7627S 软件模拟器

这是**当前 Windows 环境的核心**，真实硬件就绪后整文件替换。

**波形生成原理**：

```
va(t) = Vpeak * sin(2*pi*50*t)                              // 基波
      + Vpeak * hv[n]/100 * sin(2*pi*50*n*t)               // 各次谐波电压
      + noise                                              // 高斯白噪声

ia(t) = Ipeak * sin(2*pi*50*t - phi)                       // 基波电流
      + Ipeak * hi[n]/100 * sin(2*pi*50*n*t - phi)        // 各次谐波电流
      + noise
```

其中 `phi = acos(power_factor)` 为功率因数角。

**关键设计**：
- 电压峰值由 `Vnom * sqrt(2) * (1 + voltage_offset/100)` 计算，确保 RMS 准确。
- 电流由三相功率公式反推：`Ipeak = S_apparent / (3 * Vphase_RMS) * sqrt(2)`。
- 噪声使用 Box-Muller 算法生成高斯白噪声，SNR 约 55~60 dB。
- 寄存器值（RMS、THD、功率等）**从生成的波形实时计算**，保证数据一致性。

**5 个仿真场景参数**：

| 参数 | S1 基准 | S2 充电桩 | S3 光伏 | S4 光充耦合 | S5 极端 |
|------|---------|-----------|---------|-------------|---------|
| 电压偏移 | 0% | 0% | +2.93% | +2.93% | +3.5% |
| 负荷有功 | 340 kW | 80 kW | 200 kW | 280 kW | 360 kW |
| 功率因数 | 0.85 | 0.95 | 1.0 | 0.95 | 0.90 |
| 电压 THD | 0% | 5% | 0% | 5% | 8% |
| 电流 THD | 0% | 20% | 0% | 20% | 25% |
| 谐波次数 | 无 | 5/7/11/13 | 无 | 5/7/11/13 | 5/7/11/13 |

### 3.4 核心算法层（core/）

#### 3.4.1 `pq_metrics.c` —— 12 项 PQ 指标计算

**核心结构体**：

```c
typedef struct {
    char     name[32];
    float    value;       /* 实测值 */
    float    limit;       /* 国标限值 */
    int      status;      /* 0=正常, 1=预警, 2=超标 */
    uint32_t timestamp;
    float    confidence;  /* 置信度 */
} pq_metric_t;
```

**12 项指标清单**：

| 序号 | 指标 | 计算方式 | 国标限值（默认可配置） |
|------|------|----------|------------------------|
| 1 | 电压偏差 | `(Vrms - Vnom) / Vnom * 100%` | ±7% |
| 2 | 电压 THD | 直接从 HT7627S 寄存器读取 | 5% |
| 3 | 电流 THD | 直接从 HT7627S 寄存器读取 | 8% |
| 4 | 电压不平衡度 | 对称分量法简化版 | 2% |
| 5 | 频率偏差 | `\|f - 50\|` | 0.5 Hz |
| 6 | 变压器负载率 | `S_apparent / S_rated * 100%` | 100% |
| 7 | 线路负载率 | `I_rms_avg / I_max * 100%` | 100% |
| 8 | 功率因数 | `P / S` | 0.85 |
| 9 | 有功功率 | 直接从寄存器 | — |
| 10 | 无功功率 | 90° 相移法计算 | — |
| 11 | 视在功率 | `sqrt(P² + Q²)` | — |
| 12 | 3 次谐波含有率 | 寄存器 harmonics[2] | 5% |

**限值配置化**：

所有限值不再写死为宏，而是通过 `pq_metrics_set_limits()` 在运行时设置，支持从 `config.ini` 读取：

```c

    config_get_float(&cfg, "thresholds.voltage_deviation_limit", 7.0f),
    config_get_float(&cfg, "thresholds.voltage_thd_limit", 5.0f),
    config_get_float(&cfg, "thresholds.current_thd_limit", 8.0f),
    config_get_float(&cfg, "thresholds.unbalance_limit", 2.0f),
    config_get_float(&cfg, "thresholds.frequency_deviation_limit", 0.5f),
    config_get_float(&cfg, "thresholds.transformer_load_limit", 100.0f),
    config_get_float(&cfg, "thresholds.line_load_limit", 100.0f),
    config_get_float(&cfg, "thresholds.power_factor_limit", 0.85f)
);
```

#### 3.4.2 `event_trigger.c` —— 事件触发引擎

**7 类事件**：

```c
#define EVENT_TYPE_VOLTAGE_SAG    1   /* 电压暂降 */
#define EVENT_TYPE_VOLTAGE_SWELL  2   /* 电压暂升 */
#define EVENT_TYPE_HARMONIC       3   /* 谐波超标 */
#define EVENT_TYPE_UNBALANCE      4   /* 不平衡超标 */
#define EVENT_TYPE_OVERLOAD       5   /* 过载 */
#define EVENT_TYPE_FREQ_DEV       6   /* 频率偏差 */
#define EVENT_TYPE_SCENARIO_CHG   7   /* 场景变化 */
```

**滞回机制**（防止事件频繁抖动）：

- **进入条件**：指标值 ≥ 限值的 90%
- **退出条件**：指标值 ≤ 限值的 92%（且此前已进入）

**严重度计算**：

```
severity = min(10.0, 10.0 * value / limit)
```

例如：电压 THD 实测 6.89%，限值 5%，则严重度 = 10 * 6.89 / 5 = 13.78，截断为 10.0（最高级）。

#### 3.4.3 `wave_freeze.c` —— 波形冻结与环形缓冲

**设计目标**：当事件触发时，保存触发前 10 周波 + 触发后 20 周波的完整波形，共 30 周波，用于后续 AI 分析与故障回溯。

**缓冲区结构**：

```c
#define WAVE_FREEZE_PRE_CYCLES   10
#define WAVE_FREEZE_POST_CYCLES  20
#define WAVE_FREEZE_MAX_CYCLES   30

typedef struct {
    wave_cycle_t cycles[30];    /* 30 周波 * 7 通道 * 512 点 */
    uint16_t     head;          /* 写入位置 */
    uint16_t     count;         /* 有效周波数 */
    uint8_t      frozen;        /* 是否已冻结 */
    uint32_t     frozen_cycle;  /* 冻结时刻周波号 */
} wave_freeze_buffer_t;
```

**工作流程**：

1. 正常运行时，`wave_freeze_push()` 每周期写入新波形，覆盖最旧数据（环形缓冲）。
2. 事件触发时，`wave_freeze_trigger()` 设置 `frozen = 1`，停止写入。
3. 后续继续收集 `POST_CYCLES`（20 个周波）后，波形完整。
4. `wave_freeze_get_frozen()` 可读取冻结的 30 周波数据。
5. 事件恢复后，`wave_freeze_reset()` 重置缓冲区，恢复写入。

|------|------|----------|
| 标准特征 | 16 | 电压/电流 RMS、功率、THD、不平衡度、频偏、负载率、谐波含有率等 |
| 波形特征 | 11 | 波峰因数、波形因数、面积、斜率统计、过零点、近似熵、峰峰值、半波不对称度、复杂度、瞬态能量 |
| **合计** | **27** | — |

波形特征对三相电压通道分别计算后取平均，增强鲁棒性。

```c
#define N_STD_FEATURES   16
#define N_WAVE_FEATURES  11
#define N_TOTAL_FEATURES 27

typedef struct {
    float features[27];
    char  names[27][32];
    uint16_t n_features;
} feature_vector_t;
```

#### 3.4.5 `scenario_detect.c` —— 场景识别

**S1~S5 判定规则**（基于 PQ 指标阈值）：

| 场景 | 判定条件 |
|------|----------|
| S2 充电桩 | 电流 THD > 8% 且 变压器负载率 < 40% |
| S3 光伏 | 电压偏差 > 2% 且 电压 THD 在 1.5%~5% 且 电流 THD < 5% |
| S4 光充耦合 | 同时满足电压抬升 + 谐波电流特征（S2 和 S3 的交集） |
| S5 极端 | 电压 THD > 7% 或 电流 THD > 20% 或 负载率 > 90% |
| S1 基准 | 不满足以上任何条件 |

**治理建议**：每个场景返回对应的文字建议，供上位机展示或本地日志记录。

### 3.5 AI 推理层（ai/）

> **当前状态**：全部为 Stub 实现，使用随机权重模拟推理流程。待 NPU 工具链就绪后，替换为 INT8 量化模型。

#### 3.5.1 `iforest_infer.c` —— 孤立森林异常检测

- **模型结构**：32 棵随机树，最大深度 8，27 维输入。
- **异常得分**：`score = 2^(-avg_depth / c(n))`，其中 `c(n)` 为归一化因子。
- **判定**：`score > 0.6` 视为异常（阈值可在 `config.ini` 调整）。
- **模型加载**：支持从二进制文件加载，失败时自动生成随机树（固定种子 42），保证结果可复现。

#### 3.5.2 `ae_infer.c` —— 自编码器异常检测

- **网络结构**：27（输入）→ 8（隐层）→ 27（输出），线性变换模拟。
- **异常得分**：重构误差 MSE = `mean((x - x_hat)²)`。
- **判定**：MSE > 阈值视为异常。

#### 3.5.3 `cnn1d_infer.c` —— 1D-CNN 事件分类

- **输入**：7 通道 × 256 点/周波 × N 周波。
- **网络结构**：8 滤波器，5 点卷积核，全连接层，Softmax 输出。
- **输出类别**：

```c
CNN_CLASS_NORMAL     = 0   /* 正常 */
CNN_CLASS_SAG        = 1   /* 电压暂降 */
CNN_CLASS_SWELL      = 2   /* 电压暂升 */
CNN_CLASS_HARMONIC   = 3   /* 谐波事件 */
CNN_CLASS_UNBALANCE  = 4   /* 不平衡 */
CNN_CLASS_OVERLOAD   = 5   /* 过载 */

```

### 4.2 主循环详解（sim_main.c）

```c
for (i = 0; i < max_cycles; i++) {
    /* 1. 读取 HT7627S 数据 */
    hal_ht7627s_read_regs(&regs);
    hal_ht7627s_read_wave(&wave);

    /* 2. 计算 PQ 指标 */
    pq_metrics_calculate(&regs, &wave, &metrics);
    pq_metrics_evaluate(&metrics);

    /* 3. 波形写入环形缓冲 */
    wave_freeze_push(&wbuf, &wave);

    /* 4. 事件检测 */
    if (event_trigger_check(&metrics, &event) == 1) {
        wave_freeze_trigger(&wbuf, wave.cycle_id);
        db_save_event(&event);
        mqtt_publish("pq/terminal/event", json_buf, 1);
    }

    /* 5. 特征提取 + AI 推理 */
    feature_extract_from_wave(wbuf.cycles, wbuf.count, &metrics, &feat);
    float if_score = iforest_score(&if_model, feat.features);
    float ae_score = ae_anomaly_score(feat.features);

    /* 6. 场景识别 */
    scen = scenario_detect_classify(&metrics, &feat);

    /* 7. 周期性上报（每 50 周期） */
    if (i % 50 == 0) {
        mqtt_publish("pq/terminal/status", json_buf, 0);
    }

    /* 8. 保存指标 */
    db_save_metrics(&metrics);

    /* 9. 模拟 20ms 周期 */
    hal_sleep_ms(20);
}
```

### 4.3 指标评估逻辑（pq_metrics_evaluate）

每个指标独立评估，状态分为三级：

| 状态码 | 含义 | 判定条件 |
|--------|------|----------|
| 0 | 正常 | `value < limit` |
| 1 | 预警 | `limit <= value < limit * 1.2` |
| 2 | 超标 | `value >= limit * 1.2` |

**特殊处理——功率因数**：

功率因数是"越高越好"，与其他指标方向相反：

```c
if (pf < limit)        status = 2;  /* 超标 */
else if (pf < limit * 1.06) status = 1;  /* 预警 */
else                   status = 0;  /* 正常 */
```

### 6.1 编码规范

### 6.3 平台抽象原则

**核心原则**：业务代码（`core/`, `ai/`, `comm/`）不得直接调用平台 API。

| 平台相关操作 | 应调用 | 实现位置 |
|--------------|--------|----------|

| TCP 套接字 | `proto_mqtt.c` 内部封装 | `comm/proto_mqtt.c` |

### 6.4 浮点运算注意事项

- 所有浮点常量显式加 `f` 后缀，避免隐式双精度转换：
  ```c
  float x = 3.14159265f;   /* 正确 */
  float y = 3.14159265;    /* 错误：隐含 double */
  ```
- 比较浮点数使用容差：
  ```c
  #define EPSILON 1e-6f
  if (fabsf(a - b) < EPSILON) { /* 相等 */ }
  ```

### 6.5 内存管理

- **禁止在核心算法中使用动态内存分配**（`malloc` / `free`）。
- 所有缓冲区使用静态数组或调用方传入的栈内存。
- 栈空间敏感环境下，大数组使用 `static` 修饰或移至全局区。

### 6.6 调试技巧

### 7.2 如何替换 AI Stub 为真实模型

#### 孤立森林（iForest）

**当前**：`ai/iforest_infer.c` 使用随机生成的树，固定种子 42。

**替换步骤**：
1. 使用 Python `sklearn.ensemble.IsolationForest` 训练模型。
2. 将树的结构（节点阈值、特征索引、左右子树指针）导出为 C 数组。
3. 替换 `iforest_load_model()`，从导出的 C 数组构建树结构。
4. `iforest_score()` 的遍历逻辑保持不变，仅需替换树数据来源。

#### 自编码器（AE）

**当前**：线性变换模拟编码/解码。

**替换步骤**：
1. 使用 PyTorch/TensorFlow 训练 AE，输入 27 维，隐层 8 维。
2. 量化权重至 INT8（若部署到 NPU）。
3. 替换 `ae_init()` 中的 `W1`, `b1`, `W2`, `b2` 为真实权重数组。
4. 激活函数从线性改为 `tanh` 或 `ReLU`（与训练时一致）。

#### 1D-CNN

**当前**：随机卷积核 + 全连接层。

**替换步骤**：
1. 训练 1D-CNN 分类器（输入 7×256，输出 7 类）。
2. 通过 T536 NPU SDK 将 ONNX 模型转换为 `.nb` 格式。
3. 替换 `cnn1d_infer.c` 为 NPU 推理 API 调用（如 `tnn::Instance::Forward()`）。
4. 若 NPU 暂不可用，可先使用 `CMSIS-NN` 在 CPU 上跑 INT8 推理。

### 7.3 如何移植到真实 HT7627S

**核心：替换 `sim/hal_sim.c` 为真实驱动**

```c
/* drivers/ht7627s_drv.c —— 真实驱动示例框架 */

#include "pq_hal.h"
#include "ht7627s_regs.h"   /* 寄存器地址宏 */

static int s_spi_fd = -1;

int hal_ht7627s_init(const ht7627s_cfg_t *cfg)
{
    /* 1. 初始化 SPI 总线（T536 的 SPI0/SPI1） */
    s_spi_fd = spi_open("/dev/spidev0.0", 1000000); /* 1MHz */
    
    /* 2. 写入 HT7627S 配置寄存器 */
    ht7627s_write_reg(ADDR_SAMPRATE, cfg->sample_rate);
    ht7627s_write_reg(ADDR_CHANNELS, cfg->n_channels);
    
    /* 3. 启动 ADC 连续采样 */
    ht7627s_write_reg(ADDR_CTRL, CTRL_ADC_EN | CTRL_DMA_EN);
    
    return 0;
}

int hal_ht7627s_read_regs(ht7627s_regs_t *regs)
{
    /* 批量读取 RMS、THD、功率等计算结果寄存器 */
    uint8_t buf[REG_BURST_LEN];
    ht7627s_read_burst(ADDR_RMS_START, buf, REG_BURST_LEN);
    
    /* 解析寄存器值（注意 HT7627S 的数据格式，可能是 24bit 定点数） */
    regs->rms[0] = parse_24bit_fixed(buf + 0) * VOLTAGE_SCALE;
    /* ... */
    
    return 0;
}

int hal_ht7627s_read_wave(ht7627s_wave_t *wave)
{
    /* 从 DMA 环形缓冲读取原始采样点 */
    /* 或使用 HT7627S 的波形缓存模式 */
    dma_read_wave_buffer(wave->samples, wave->valid_samples);
    wave->cycle_id = g_cycle_counter++;
    return 0;
}
```

**注意事项**：
- HT7627S 寄存器值可能是 24bit 定点格式，需确认量程和缩放因子。
- SPI 读取波形数据量很大（7 通道 × 256 点 × 4 字节 ≈ 7KB/周期），建议使用 DMA。
- E907 RISC-V 核负责实时 SPI 采集，A55 核负责指标计算和 AI 推理，需通过 `rpmsg` 核间通信。
