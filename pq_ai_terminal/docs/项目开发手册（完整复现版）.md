## 1. 项目概述

### 1.1 项目背景

本项目是"基于终端波形数据的电能质量 AI 应用"的完整解决方案，包含 **MATLAB 仿真验证** 与 **嵌入式软件实现** 两个子系统，核心目标是：

- **MATLAB 仿真**：基于电路方程和功率流分析的纯 MATLAB 时域仿真，评估分布式光伏及电动汽车充电桩接入对配电网电能质量的影响，生成 AI 训练数据集。
- **实时采集**：通过 HT7627S 高精度计量芯片，以 12.8 kHz 采样率同步采集 7 通道（3 相电压 + 3 相电流 + 零序）波形数据。
- **指标计算**：实时计算电压偏差、THD、三相不平衡度、频率偏差、变压器/线路负载率等 12 项电能质量指标。
- **事件检测**：基于国标限值，检测电压暂降/暂升、谐波超标、不平衡、过载等异常事件。
- **AI 推理**：通过 USB ECM 将特征向量发送至 RK3576 算力模组，运行 iForest、AE、CNN1D 等模型，实现异常检测与事件分类。
- **场景识别**：自动识别 S1~S5 五类典型场景（基准负荷、充电桩、分布式光伏、光充耦合、极端工况），并给出治理建议。
- **数据上报**：通过 MQTT 将指标、事件、AI 结果上报云端；本地持久化存储波形与日志。

### 1.2 硬件平台

### 2.2 数据流时序

主机侧每 20ms（一个工频周波）执行一次完整流程：

```
T0      T1      T2      T3      T4      T5      T6      T7      T8      T9
│       │       │       │       │       │       │       │       │       │
▼       ▼       ▼       ▼       ▼       ▼       ▼       ▼       ▼       ▼
HT7627S → HAL → PQ指标 → 波形冻结 → 事件检测 → 特征提取 → AI RPC → 场景识别 → 持久化 → MQTT
 读取    解析    计算     缓冲      滞回判断   27维特征   USB ECM   规则判断   CSV/DB  上报
                                                          ↓
                                              （USB ECM 虚拟网卡传输）
                                                          ↓
                                              RK3576 接收 → iForest/AE/CNN 推理 → 返回 JSON
```

### 2.3 USB ECM 通信原理

**USB ECM（Ethernet Control Model）** 是 USB 通信设备类（CDC）标准的一部分，将 USB 物理链路抽象为虚拟以太网卡：

1. **物理层**：T536 的 USB Host 口通过 USB 数据线连接 RK3576 的 USB Device 口。
2. **驱动层**：Linux 内核加载 `cdc_ether` 或 `rndis_host` 驱动，自动枚举出 `usb0` 网卡。
3. **网络层**：两端通过 DHCP 或静态 IP 分配地址（RK3576=192.168.100.1，T536=192.168.100.x），子网掩码 255.255.255.0。
4. **传输层**：上层应用使用标准 TCP Socket 通信，对应用代码完全透明。
5. **应用层**：主机侧 `ai_rpc.c` 发送 JSON 请求，算力模组侧 `rk3576_inference_server.py` 返回 JSON 应答。

**优势**：
- 跨平台：Windows（Winsock2）和 Linux（BSD socket）API 完全一致。
- 可复用：直接使用标准 socket 编程，无需学习 USB 专用 API。
- 可仿真：无硬件时退化为本地回环 `127.0.0.1`，调试零成本。

### 4.2 公共头文件（include/）

所有 `.c` 文件都应首先包含此头文件。它定义了：

本章节对每个核心模块按 **功能实现原理 → 算法说明 → 仿真方法 → 软件编码** 四部分详细阐述，确保无相关背景的新入职人员能够快速理解。

### 5.1 HT7627S 采样与 HAL 仿真层（sim/hal_sim.c）

#### 5.1.1 功能实现原理

**核心功能**：模拟钜泉 HT7627S 计量 AFE 芯片的采样行为，向上层提供统一的寄存器读取接口与波形读取接口。

**设计思路**：HT7627S 是一颗 7 通道 24bit 高精度 ADC，内置谐波分析引擎。在无真实硬件时，由 `hal_sim.c` 完整模拟其行为：

1. 根据场景参数（S1~S5）生成时域电压/电流波形。
2. 从波形实时计算 RMS、THD、功率、谐波等寄存器值。
3. 维护 cycle_id 计数与时间戳，模拟 DMA 周期性输出。
4. 提供互斥锁保护，确保多线程安全。

**工作流程**：
```
hal_ht7627s_init(cfg)        ← 初始化（采样率、通道数、场景）
    ↓
hal_set_sim_scenario("S4")   ← 设置场景
    ↓
循环 {
    hal_ht7627s_read_regs()  ← 读取寄存器（RMS/THD/功率）
    hal_ht7627s_read_wave()  ← 读取原始波形（256点×7通道）
}
    ↓
hal_ht7627s_close()          ← 关闭
```

#### 5.1.2 算法说明

**波形生成算法**：基于解析时域叠加法

电压波形：
```
va(t) = Vpeak · sin(2π·50·t)                         // 基波
      + Σ Vpeak · (hv[n]/100) · sin(2π·50·n·t)        // 各次谐波电压
      + noise                                          // 高斯白噪声
```

电流波形：
```
ia(t) = Ipeak · sin(2π·50·t - φ)                      // 基波电流
      + Σ Ipeak · (hi[n]/100) · sin(2π·50·n·t - φ)    // 各次谐波电流
      + noise
```

其中 `φ = arccos(power_factor)` 为功率因数角。

**关键参数推导**：
- 电压峰值：`Vpeak = Vnom · √2 · (1 + voltage_offset/100)`，确保 RMS 准确。
- 电流峰值：`Ipeak = S_apparent / (3 · Vphase_RMS) · √2`，由三相功率公式反推。
- 高斯白噪声：Box-Muller 算法生成，SNR 约 55~60 dB。

**RMS 计算公式**：
```
Vrms = √( (1/N) · Σ v[i]² )     （N = 每周波采样点数）
```

**THD 计算公式**：
```
THD = √(Σ Hn²) / H1 · 100%       （n=2,3,...,31）
```

其中 Hn 为第 n 次谐波幅值，H1 为基波幅值，由 FFT 提取。

**5 个仿真场景参数**：

| 参数 | S1 基准 | S2 充电桩 | S3 光伏 | S4 光充耦合 | S5 极端 |
|------|---------|-----------|---------|-------------|---------|
| 电压偏移 | 0% | 0% | +2.93% | +2.93% | +3.5% |
| 负荷有功 | 340 kW | 80 kW | 200 kW | 280 kW | 360 kW |
| 功率因数 | 0.85 | 0.95 | 1.0 | 0.95 | 0.90 |
| 电压 THD | 0% | 5% | 0% | 5% | 8% |
| 电流 THD | 0% | 20% | 0% | 20% | 25% |
| 谐波次数 | 无 | 5/7/11/13 | 无 | 5/7/11/13 | 5/7/11/13 |

#### 5.1.3 仿真方法

**仿真环境配置**：
- 采样率：12800 Hz（HT7627S 默认）
- 每周波点数：256（对应 50Hz 工频）
- 通道数：7（3 电压 + 3 电流 + 1 零序）
- 周期：20ms（一个工频周波）

### 5.2 PQ 指标计算模块（core/pq_metrics.c）

#### 5.2.1 功能实现原理

**核心功能**：根据 HT7627S 寄存器数据，实时计算 12 项国标电能质量指标，并按 GB/T 12325/14549/15543/15945 限值评估状态。

**设计思路**：
1. 每个指标封装为 `pq_metric_t` 结构体，包含名称、实测值、限值、状态、置信度。
2. 限值通过 `pq_metrics_set_limits()` 在运行时设置，支持从 `config.ini` 读取。
3. 状态评估采用三级：正常(0) / 预警(1) / 超标(2)。
4. 所有浮点常量显式加 `f` 后缀，避免 double 隐式转换。

**工作流程**：
```
HT7627S 寄存器 → pq_metrics_calculate() → 12 项指标填充
                → pq_metrics_evaluate()   → 状态评估（0/1/2）
```

#### 5.2.2 算法说明

**12 项指标清单与公式**：

| 序号 | 指标 | 计算公式 | 国标 | 限值 |
|------|------|----------|------|------|
| 1 | 电压偏差 | `(Vrms_avg - Vnom) / Vnom × 100%` | GB/T 12325 | ±7% |
| 2 | 电压 THD | 直接从 HT7627S 寄存器读取 | GB/T 14549 | 5% |
| 3 | 电流 THD | 直接从 HT7627S 寄存器读取 | GB/T 14549 | 8% |
| 4 | 电压不平衡度 | `max(|Va-Vavg|, |Vb-Vavg|, |Vc-Vavg|) / Vavg × 100%` | GB/T 15543 | 2% |
| 5 | 频率偏差 | `|f - 50|` | GB/T 15945 | 0.5 Hz |
| 6 | 变压器负载率 | `S_apparent / S_rated × 100%` | — | 100% |
| 7 | 线路负载率 | `I_rms_avg / I_max × 100%` | — | 100% |
| 8 | 功率因数 | `P / S` | — | 0.85 |
| 9 | 有功功率 | 直接从寄存器 | — | — |
| 10 | 无功功率 | 90° 相移法 | — | — |
| 11 | 视在功率 | `√(P² + Q²)` | — | — |
| 12 | 3 次谐波含有率 | `regs.harmonics[2]` | GB/T 14549 | 5% |

**不平衡度简化算法推导**：

国标 GB/T 15543 推荐对称分量法，但需完整三相复数运算。本模块采用 RMS 简化版：
```
Vavg = (Va + Vb + Vc) / 3
ΔVmax = max(|Va - Vavg|, |Vb - Vavg|, |Vc - Vavg|)
Unbalance = ΔVmax / Vavg × 100%
```
此简化在幅值不平衡场景下精度足够，相位不平衡需后续扩展 FFT 法。

**状态评估算法**：
```
abs(value) > limit           → status = 2 (超标)
abs(value) > limit × 0.9     → status = 1 (预警)
否则                          → status = 0 (正常)
```
功率因数为反向指标（越低越差），单独处理：低于 `limit` 为超标，低于 `limit × 1.06` 为预警。

**关键代码片段**（不平衡度简化计算）：

```c
static float calc_unbalance_rms(const ht7627s_regs_t *regs)
{
    float va = regs->rms[0];
    float vb = regs->rms[1];
    float vc = regs->rms[2];
    float v_avg = (va + vb + vc) / 3.0f;
    float v_max_dev = fabsf(va - v_avg);
    float dev;

    dev = fabsf(vb - v_avg);
    if (dev > v_max_dev) v_max_dev = dev;
    dev = fabsf(vc - v_avg);
    if (dev > v_max_dev) v_max_dev = dev;

    if (v_avg > 1.0f) {
        return (v_max_dev / v_avg) * 100.0f;
    }
    return 0.0f;
}
```

**开发环境搭建**：参考第 3 章环境搭建。本模块为纯 C99 实现，无外部依赖，仅包含 `<math.h>` 与 `<string.h>`。

### 5.3 事件触发引擎（core/event_trigger.c）

#### 5.3.1 功能实现原理

**核心功能**：基于 PQ 指标实时检测 7 类电能质量事件，采用滞回机制避免指标在限值附近抖动时频繁误触发。

**设计思路**：
1. 每类事件维护一个独立的状态位（active/inactive）。
2. 进入阈值：指标超过限值的 90% 时触发事件。
3. 退出阈值：指标回落至限值的 92% 以下时清除事件。
4. 严重度计算：`severity = min(10, |value| / limit)`，量化事件严重程度。

**工作流程**：
```
PQ 指标 → event_trigger_check() → 逐项检查滞回
                                   → 触发：返回 1 + 填充 event 结构体
                                   → 未触发：返回 0
```

#### 5.3.2 算法说明

**7 类事件**：

```c
#define EVENT_TYPE_VOLTAGE_SAG    1   /* 电压暂降（v_dev < -10%） */
#define EVENT_TYPE_VOLTAGE_SWELL  2   /* 电压暂升（v_dev > +10%） */
#define EVENT_TYPE_HARMONIC       3   /* 谐波超标（电压/电流 THD） */
#define EVENT_TYPE_UNBALANCE      4   /* 三相不平衡超标 */
#define EVENT_TYPE_OVERLOAD       5   /* 变压器/线路过载 */
#define EVENT_TYPE_FREQ_DEV       6   /* 频率偏差超标 */
#define EVENT_TYPE_SCENARIO_CHG   7   /* 场景变化 */
```

**滞回机制公式**：

```
若指标当前未激活：
    触发条件 = |value| > limit × 0.90    → 激活事件，返回 triggered=1
若指标当前已激活：
    保持条件 = |value| > limit × 0.92    → 保持激活
    退出条件 = |value| ≤ limit × 0.92    → 清除激活
```

**严重度计算公式**：
```
severity = min(10.0, |value| / limit)
```
- severity ∈ [0, 1]：预警级别
- severity ∈ [1, 10]：超标级别，数值越大越严重

**滞回系数选择依据**：
- 进入阈值 0.90：留 10% 余量，避免指标在限值 90%~100% 之间频繁触发。
- 退出阈值 0.92：与进入阈值相差 2%，形成滞回带，防止抖动。
- 两值均小于 1.0，确保只有指标接近或超过限值时才触发。

#### 5.3.3 仿真方法

**仿真环境配置**：
- 滞回系数：`HYST_ENTER = 0.90`，`HYST_EXIT = 0.92`（硬编码）
- 事件 ID：自增计数器，从 1 开始

**关键参数设置**：
事件触发依赖于 `config.ini` 中 `[thresholds]` 段的限值。修改限值会直接影响触发频率。

**仿真步骤**：
1. 调用 `event_trigger_init()` 清空状态。
2. 主循环中：`event_trigger_check(&metrics, &event)`。
3. 返回 1 时：`event_count++`，调用 `wave_freeze_trigger()` 冻结波形，`db_save_event()` 持久化，`mqtt_publish()` 上报。

**结果分析方法**：
- S1 基准：event_count = 0（所有指标 NORMAL）。
- S2 充电桩：event_count = max_cycles（电流 THD 持续超标）。
- 检查 `event.type` 与 `event.description` 是否与场景匹配。
- 检查 `event.severity` 是否在合理范围（0~10）。

#### 5.3.4 软件编码

**事件结构体**：

```c
typedef struct {
    uint32_t id;                   /* 事件唯一 ID */
    uint8_t  type;                 /* 事件类型码 */
    uint32_t start_ts;             /* 起始时间戳 */
    uint32_t end_ts;               /* 结束时间戳 */
    float    severity;             /* 严重度 [0,10] */
    uint8_t  phase;                /* 相别 */
    pq_metric_t trigger_metric;    /* 触发指标快照 */
    char     description[128];     /* 事件描述 */
} pq_event_t;
```

**核心函数**：

```c

/* 检查是否触发事件（每周期调用一次） */
int event_trigger_check(const pq_metrics_t *metrics,
                        pq_event_t *event_out);
/* 返回值：0=未触发，1=触发，<0=错误 */
```

**关键代码片段**（滞回检查）：

```c
static int hysteresis_check(int active, uint8_t *state,
                            float enter_thr, float exit_thr)
{
    if (active) {
        if (*state == 0) {
            if (enter_thr >= 0.0f) {
                *state = 1;
                return 1;   /* 新触发 */
            }
        } else {
            return 1;       /* 保持激活 */
        }
    } else {
        if (*state == 1) {
            if (exit_thr >= 0.0f) {
                *state = 0; /* 退出 */
            } else {
                return 1;   /* 仍保持 */
            }
        }
    }
    return 0;
}
```

**关键代码片段**（严重度计算）：

```c
static float calc_severity(float value, float limit)
{
    float ratio;
    if (limit <= 0.0f) return 0.0f;
    ratio = fabsf(value) / limit;
    if (ratio > 1.0f) {
        return (ratio > 10.0f) ? 10.0f : ratio;
    }
    return ratio;
}
```

### 5.4 波形冻结模块（core/wave_freeze.c）

#### 5.4.1 功能实现原理

**核心功能**：在事件触发时，冻结触发前 10 周波 + 触发后 20 周波的完整波形数据，共 30 周波，用于后续 AI 分析与故障回溯。

**设计思路**：
1. 维护一个环形缓冲区，持续缓存最近 10 个周波的波形。
2. 事件触发时，标记冻结状态，继续缓存 20 个周波后停止。
3. 冻结期间的数据用于 AI 推理输入与离线分析。

**工作流程**：
```
每周期 → wave_freeze_push(&wbuf, &wave)  ← 持续缓存
事件触发 → wave_freeze_trigger(&wbuf, cycle_id)  ← 标记冻结起点
事件后 20 周波 → wave_freeze_reset(&wbuf)  ← 清除冻结，恢复缓存
```

#### 5.4.2 算法说明

**环形缓冲区算法**：
- 缓冲区大小：`WAVE_FREEZE_PRE_CYCLES + WAVE_FREEZE_POST_CYCLES = 10 + 20 = 30`
- 写入索引：`wbuf.write_idx = (wbuf.write_idx + 1) % capacity`
- 冻结后：停止写入，等待读取完毕后 reset。

**冻结窗口计算**：
```
冻结起点 = trigger_cycle
冻结终点 = trigger_cycle + 20
有效数据范围 = [trigger_cycle - 10, trigger_cycle + 20]
```

#### 5.4.3 仿真方法

**仿真环境配置**：
- `WAVE_FREEZE_PRE_CYCLES = 10`（触发前缓存周波数）
- `WAVE_FREEZE_POST_CYCLES = 20`（触发后缓存周波数）

**仿真步骤**：
1. 调用 `wave_freeze_init(&wbuf)` 初始化。
2. 主循环：`wave_freeze_push(&wbuf, &wave)` 持续缓存。
3. 事件触发时：`wave_freeze_trigger(&wbuf, wave.cycle_id)`。
4. 主循环中检查：`if (wbuf.frozen && (i - wbuf.frozen_cycle) > WAVE_FREEZE_POST_CYCLES) wave_freeze_reset(&wbuf);`

**结果分析方法**：
- 检查 `wbuf.count` 在触发后是否正确递增至 30。
- 检查 `wbuf.cycles[]` 数组中的 `cycle_id` 是否连续。
- 从冻结波形中提取特征向量，验证 AI 推理输入正确性。

#### 5.4.4 软件编码

**核心函数**：

```c
/* 初始化波形冻结缓冲 */
void wave_freeze_init(wave_freeze_buffer_t *wbuf);

/* 推入一个周波（每周期调用） */
void wave_freeze_push(wave_freeze_buffer_t *wbuf, const ht7627s_wave_t *wave);

/* 触发冻结 */
void wave_freeze_trigger(wave_freeze_buffer_t *wbuf, uint32_t cycle_id);

/* 重置冻结状态 */
void wave_freeze_reset(wave_freeze_buffer_t *wbuf);
```

**关键代码片段**（环形缓冲写入）：

```c
void wave_freeze_push(wave_freeze_buffer_t *wbuf, const ht7627s_wave_t *wave)
{
    if (wbuf->frozen) return;  /* 冻结期间停止写入 */

    /* 复制波形到环形缓冲 */
    wbuf->cycles[wbuf->write_idx] = *wave;
    wbuf->write_idx = (wbuf->write_idx + 1) % WAVE_FREEZE_PRE_CYCLES;
    if (wbuf->count < WAVE_FREEZE_PRE_CYCLES) wbuf->count++;
}
```

### 5.5 特征工程模块（core/feature_extract.c）

#### 5.5.1 功能实现原理

**核心功能**：从冻结波形与 PQ 指标中提取 27 维特征向量，作为 AI 推理的输入。

**设计思路**：
1. 特征分为两大类：标准特征（16 维）+ 波形特征（11 维）= 27 维。
2. 标准特征：从 PQ 指标直接提取（电压偏差、THD、功率、负载率等）。
3. 波形特征：从时域波形统计计算（波峰因数、波形因数、过零点、近似熵等）。
4. 输出统一封装为 `feature_vector_t`，附带特征名称。

#### 5.5.2 算法说明

**27 维特征清单**：

| 类别 | 维度 | 特征说明 |
|------|------|----------|
| 标准特征 | 16 | 电压/电流 RMS、功率、THD、不平衡度、频偏、负载率、谐波等 |
| 波形特征 | 11 | 波峰因数、波形因数、面积、斜率统计、过零点、近似熵、峰峰值、半波不对称度、复杂度、瞬态能量 |
| **合计** | **27** | — |

**关键波形特征公式**：

1. **波峰因数（Crest Factor）**：
   ```
   CF = Vpeak / Vrms
   ```
   正弦波 CF = √2 ≈ 1.414，谐波导致波形尖峰化时 CF 增大。

2. **波形因数（Form Factor）**：
   ```
   FF = Vrms / Vavg_rectified
   ```
   正弦波 FF = π/(2√2) ≈ 1.111。

3. **近似熵（Approximate Entropy）**：
   衡量波形复杂度，正常正弦波熵值低，谐波/瞬态导致熵值升高。

4. **半波不对称度**：
   ```
   Asym = |Σ(v[i] for i in 正半周) - |Σ(v[i] for i in 负半周)|| / Σ|v[i]|
   ```
   检测直流偏移与半波整流负荷。

5. **过零点数**：单位时间内波形穿过零点的次数，反映频率与谐波含量。

#### 5.5.3 仿真方法

**仿真环境配置**：
- 特征维度：27（`N_STD_FEATURES=16` + `N_WAVE_FEATURES=11`）
- 输入：冻结波形 `wave_cycle_t[]` + PQ 指标 `pq_metrics_t`

**仿真步骤**：
1. 调用 `feature_extract_init()` 初始化。
2. 主循环中：`feature_extract_from_wave(wbuf.cycles, wbuf.count, &metrics, &feat)`。
3. 将 `feat` 传递给 `ai_rpc_infer()` 进行 AI 推理。

**结果分析方法**：
- 检查 `feat.n_features == 27`。
- 检查各特征值是否在合理范围（无 NaN/Inf）。
- 对比不同场景下特征向量差异，验证区分度。

#### 5.5.4 软件编码

**特征向量结构体**：

```c
#define N_STD_FEATURES   16
#define N_WAVE_FEATURES  11
#define N_TOTAL_FEATURES (N_STD_FEATURES + N_WAVE_FEATURES)  /* 27 */

typedef struct {
    float features[N_TOTAL_FEATURES];
    char  names[N_TOTAL_FEATURES][32];
    uint16_t n_features;
} feature_vector_t;
```

**核心函数**：

```c

/* 从波形和指标中提取 27 维特征向量 */

                              const pq_metrics_t *metrics,
                              feature_vector_t *out);
```

**关键代码片段**（波峰因数计算）：

```c
float v_peak = 0.0f;
float v_rms = 0.0f;
for (i = 0; i < pts_per_cycle; i++) {
    float v = fabsf(wave->samples[0][i]);
    if (v > v_peak) v_peak = v;
    v_rms += wave->samples[0][i] * wave->samples[0][i];
}
v_rms = sqrtf(v_rms / pts_per_cycle);
float crest_factor = v_rms > 0.0f ? v_peak / v_rms : 0.0f;
```

### 5.6 场景识别模块（core/scenario_detect.c）

#### 5.6.1 功能实现原理

**核心功能**：根据 PQ 指标实时识别当前电网所处的典型场景（S1~S5），输出场景类型与治理建议。

**设计思路**：
1. 基于规则的判定，优先级从高到低：S5 > S4 > S2/S3 > S1。
2. 每个场景有独立的判定条件组合（多指标 AND 逻辑）。
3. 输出场景名称与对应的治理建议字符串。

#### 5.6.2 算法说明

**S1~S5 判定规则**：

| 场景 | 判定条件 | 优先级 |
|------|----------|--------|
| S5 极端 | 电压 THD > 7% **或** 电流 THD > 20% **或** 负载率 > 90% **或** 不平衡度 > 3% | 1（最高） |
| S4 光充耦合 | 电压 THD ∈ (1.5%, 8%) **且** 电压偏差 > 1% **且** 电流 THD > 5% | 2 |
| S2 充电桩 | 电流 THD > 8% **且** 变压器负载率 < 40% | 3 |
| S3 光伏 | 电压偏差 > 2% **且** 电压 THD ∈ (1.5%, 5%) **且** 电流 THD < 5% | 3 |
| S1 基准 | 不满足以上任何条件 | 4（最低） |

**规则设计依据**：
- S2 充电桩特征：电流谐波主导（5/7/11/13 次），但负荷率不高（充电桩单台功率小）。
- S3 光伏特征：电压抬升（反向潮流），但电流谐波低（逆变器滤波好）。
- S4 光充耦合：同时具备电压抬升与谐波电流特征。
- S5 极端：多个指标严重超标，需立即处置。

#### 5.6.3 仿真方法

**仿真环境配置**：纯规则判定，无参数可调（阈值硬编码）。

**仿真步骤**：
1. 调用 `scenario_detect_init()` 初始化。
2. 主循环中：`scen = scenario_detect_classify(&metrics, &feat)`。
3. 输出：`scenario_name(scen)` 与 `scenario_recommendation(scen)`。

**结果分析方法**：

| 输入场景 | 预期识别结果 | 预期建议 |
|----------|------------|----------|
| S1 基准（340kW, PF=0.85） | S1-基准负荷 | 系统运行正常，继续监测 |
| S2 充电桩（80kW, THD_i=20%） | S2-充电桩接入 | 配置 APF；有序充电策略 |
| S3 光伏（200kW, ΔV=+2.93%） | S3-分布式光伏 | 优化逆变器无功调节 |
| S4 光充耦合（280kW） | S4-光充耦合 | 配置储能系统平滑功率 |
| S5 极端（360kW, THD_i=25%） | S5-极端场景 | 立即启动负荷切除 |

#### 5.6.4 软件编码

**场景类型枚举**：

```c

    SCENARIO_S1_BASELINE,       /* S1 基准负荷 */
    SCENARIO_S2_EV_CHARGING,     /* S2 充电桩接入 */
    SCENARIO_S3_PV,              /* S3 分布式光伏 */
    SCENARIO_S4_EV_PV,           /* S4 光充耦合 */
    SCENARIO_S5_EXTREME          /* S5 极端场景 */
} scenario_type_t;
```

**核心函数**：

```c

/* 场景分类 */

                                         const feature_vector_t *feat);

/* 场景名称 */

/* 治理建议 */
```

**关键代码片段**（场景判定核心逻辑）：

```c
scenario_type_t scenario_detect_classify(const pq_metrics_t *metrics,
                                         const feature_vector_t *feat)
{
    float thd_v = metrics->voltage_thd.value;
    float thd_i = metrics->current_thd.value;
    float unbal = metrics->voltage_unbalance.value;
    float load  = metrics->transformer_load.value;
    float v_dev = metrics->voltage_deviation.value;

    /* S5 极端场景优先级最高 */
    if (thd_v > 7.0f || thd_i > 20.0f || load > 90.0f || unbal > 3.0f) {
        return SCENARIO_S5_EXTREME;
    }

    /* S2 EV 充电：电流谐波主导，负载率相对不高 */
    int is_s2 = (thd_i > 8.0f && load < 40.0f);

    /* S3 光伏：电压抬升 + 偶次谐波特征 */
    int is_s3 = (v_dev > 2.0f && thd_v > 1.5f && thd_v < 5.0f && thd_i < 5.0f);

    /* S4 光充耦合：同时有电压抬升和谐波电流 */
    int is_s4 = (thd_v > 1.5f && thd_v < 8.0f && v_dev > 1.0f && thd_i > 5.0f);

    if (is_s4 && (is_s2 || is_s3)) {
        return SCENARIO_S4_EV_PV;
    }
    if (is_s2) return SCENARIO_S2_EV_CHARGING;
    if (is_s3) return SCENARIO_S3_PV;

    return SCENARIO_S1_BASELINE;
}
```

## 6. AI 推理层技术详解

本章节详细阐述三类 AI 模型的原理、算法、仿真与编码。所有 AI 模型在 **RK3576 算力模组** 上运行，主机通过 USB ECM RPC 调用。

### 6.1 孤立森林异常检测（ai/iforest_infer.c）

#### 6.1.1 功能实现原理

**核心功能**：基于孤立森林（Isolation Forest, iForest）算法，对 27 维特征向量进行异常检测，输出异常得分 [0,1]。

**设计思路**：
- 孤立森林的核心思想：**异常点容易被随机分割隔离**。
- 构建 32 棵随机二叉树，每棵树随机选择特征与分裂点。
- 异常点在树中的路径长度短（容易被孤立），正常点路径长。
- 通过归一化路径长度计算异常得分。

**工作流程**：
```
加载模型 → 接收特征向量 → 遍历 32 棵树 → 计算平均路径长度 → 归一化为异常得分
```

#### 6.1.2 算法说明

**算法原理**：

孤立森林由 Liu et al. 于 2012 年提出，适合高维异常检测。

1. **训练阶段**：从训练集中随机采样，递归随机选择特征与分裂值，构建二叉树。
2. **推理阶段**：将待测样本遍历每棵树，记录路径长度 h(x)。
3. **归一化**：
   ```
   s(x, n) = 2^(-E(h(x)) / c(n))
   ```
   其中：
   - `E(h(x))` 为样本在所有树上的平均路径长度
   - `c(n) = 2H(n-1) - 2(n-1)/n` 为归一化因子，H 为调和级数
   - `s ∈ (0, 1)`，越接近 1 越异常

**关键参数**：

| 参数 | 值 | 说明 |
|------|-----|------|
| 树数量 `n_trees` | 32 | 森林规模，越多越稳定 |
| 树深度 `max_depth` | 8 | 单棵树最大深度 |
| 特征维度 `n_features` | 27 | 输入特征数 |
| 异常阈值 | 0.6 | 得分 > 0.6 判定为异常 |
| 样本数假设 | 256 | 用于 c(n) 计算 |

**c(n) 公式推导**：
```
H(n-1) = Σ(i=1 to n-1) 1/i        （调和级数）
c(n) = 2H(n-1) - 2(n-1)/n
```
当 n=256 时，c(256) ≈ 11.67。

**当前实现状态**：使用随机生成的树结构（Stub），待训练真实数据后替换为 `iforest_load_model()` 加载真实模型。

```c
#define IF_MAX_DEPTH     8
#define IF_N_FEATURES    27

    float thr;    /* 分裂阈值 */
    int   left;   /* 左子节点索引 */
    int   right;  /* 右子节点索引 */
} if_node_t;

typedef struct {
    if_node_t nodes[IF_MAX_TREES * (1 << IF_MAX_DEPTH)];
    int n_trees;
    int n_features;
```

**核心函数**：

```c

/* 判定异常（得分 > threshold） */
```

**关键代码片段**（树遍历）：

```c
static float traverse_tree(const if_node_t *nodes, int root,
                           const float *x, int depth)
{
    int idx = root;
    while (idx >= 0) {
        const if_node_t *node = &nodes[idx];
        if (node->left < 0 && node->right < 0) {
            return (float)depth;   /* 到达叶子节点 */
        }
        if (x[node->feat] < node->thr) {
            idx = node->left;
        } else {
            idx = node->right;
        }
        depth++;
        if (depth > IF_MAX_DEPTH + 10) break;  /* 防止死循环 */
    }
    return (float)depth;
}
```

**关键代码片段**（得分计算）：

```c
float iforest_score(const iforest_model_t *model, const float *x)
{
    float total_depth = 0.0f;
    for (int t = 0; t < model->n_trees; t++) {
        int base = t * (1 << IF_MAX_DEPTH);
        total_depth += traverse_tree(model->nodes, base, x, 0);
    }
    float avg_depth = total_depth / (float)model->n_trees;
    float c_val = c_func(256);  /* c(256) ≈ 11.67 */
    float score = powf(2.0f, -avg_depth / c_val);
    return score;  /* [0, 1]，越接近 1 越异常 */
}
```

### 6.2 自编码器异常检测（ai/ae_infer.c）

#### 6.2.1 功能实现原理

**核心功能**：基于自编码器（Autoencoder, AE）的重构误差进行异常检测，输出 MSE 重构误差作为异常得分。

**设计思路**：
- 自编码器由编码器（Encoder）和解码器（Decoder）组成。
- 训练时仅用正常样本，模型学习正常数据的压缩表示。
- 推理时，异常样本无法被正确重构，导致重构误差大。
- 误差越大，样本越可能为异常。

**网络结构**：
```
输入(27维) → 编码器 → 瓶颈层(8维) → 解码器 → 重构输出(27维)
              W1, b1               W2, b2
              tanh 激活             线性输出
```

#### 6.2.2 算法说明

**前向传播公式**：

编码器：
```
z = tanh(W1 · x + b1)        （W1: 8×27, b1: 8×1）
```

解码器：
```
x̂ = W2 · z + b2              （W2: 27×8, b2: 27×1）
```

重构误差（MSE）：
```
MSE = (1/n) · Σ(xi - x̂i)²     （n = 27）
```

**权重初始化（Xavier）**：
```
scale1 = √(2 / (input_dim + bottleneck_dim)) = √(2/35) ≈ 0.239
W1[i][j] = (rand - 0.5) × 2 × scale1
```
Xavier 初始化确保前向传播时方差稳定，避免梯度消失/爆炸。

**激活函数选择**：
- 编码器用 `tanh`：输出 [-1, 1]，适合压缩表示。
- 解码器用线性：直接输出重构值，无范围限制。

**当前实现状态**：使用 Xavier 随机初始化（Stub），待训练 PyTorch 模型后量化为 INT8 替换权重数组。

#### 6.2.3 仿真方法

**仿真环境配置**：
- 输入维度：27（`IF_N_FEATURES`）
- 瓶颈维度：8
- 内存占用：`27×8 + 8 + 8×27 + 27 = 483` 个 float ≈ 1.9KB

```ini

```

2. 接收特征向量。
3. 调用 `ae_anomaly_score(features)` 计算 MSE。
4. 返回 JSON 应答：`{"ae":12345.6789}`。

**结果分析方法**：
- 正常样本 MSE 较低（因模型已学习正常模式）。
- 异常样本 MSE 较高（重构失败）。
- 由于当前为 Stub 随机权重，MSE 绝对值无意义，仅验证流程正确性。

```c
{
    int i, j;
    for (i = 0; i < g_ae_bot_dim; i++) {
        float sum = g_b1[i];
        for (j = 0; j < g_ae_in_dim; j++) {
```

```c
{
    float mse = 0.0f;
    for (int i = 0; i < n; i++) {
        float d = x[i] - x_hat[i];
        mse += d * d;
    }
    return mse / (float)n;
}
```

### 6.3 1D-CNN 事件分类（ai/cnn1d_infer.c）

#### 6.3.1 功能实现原理

**核心功能**：基于一维卷积神经网络（1D-CNN）对波形进行事件分类，输出 7 类事件的概率分布。

**设计思路**：
- 1D-CNN 适合处理时序信号（如电力波形）。
- 卷积层提取局部特征（如谐波模式、瞬态脉冲）。
- 全局平均池化降维，全连接层输出类别概率。
- Softmax 归一化为概率分布。

**网络结构**：
```
输入(256点) → Conv1D(8滤波器×5核) → ReLU → GlobalAvgPool → FC(7类) → Softmax
```

#### 6.3.2 算法说明

**卷积运算公式**：
```
y[f][i] = Σ(j=0 to K-1) x[i+j-K/2] · W[f][j] + b[f]
```
其中：
- `f`：滤波器索引（0~7，共 8 个）
- `K = 5`：卷积核大小
- `W[f][j]`：第 f 个滤波器的第 j 个权重
- `b[f]`：偏置

**ReLU 激活函数**：
```
ReLU(x) = max(0, x)
```

**全局平均池化（Global Average Pooling）**：
```
pool[f] = (1/L) · Σ y[f][i]     （L = pts_per_cycle - K + 1）
```

**全连接层**：
```
logits[c] = Σ(f=0 to F-1) W_fc[c][f] · pool[f] + b_fc[c]
```

**Softmax 归一化**：
```
p[c] = exp(logits[c] - max(logits)) / Σ exp(logits[c'] - max(logits))
```
减去 `max(logits)` 防止指数溢出。

**7 类事件定义**：

| 类别码 | 含义 |
|--------|------|
| 0 | 正常（NORMAL） |
| 1 | 电压暂降（SAG） |
| 2 | 电压暂升（SWELL） |
| 3 | 谐波超标（HARMONIC） |
| 4 | 三相不平衡（UNBALANCE） |
| 5 | 过载（OVERLOAD） |
| 6 | 瞬态脉冲（TRANSIENT） |

**当前实现状态**：使用随机初始化权重（Stub），待训练 ONNX 模型后通过 RK3576 NPU SDK 量化部署。

- 输入点数：256（每周波）


```c
    float sum = 0.0f;
    for (i = CNN_KERNEL_SIZE / 2; i < pts_per_cycle - CNN_KERNEL_SIZE / 2; i++) {
```

```c
static void softmax(float *x, int n)
{
    float maxv = x[0];
    int i;
    for (i = 1; i < n; i++) if (x[i] > maxv) maxv = x[i];
    float sum = 0.0f;
    for (i = 0; i < n; i++) {
        x[i] = expf(x[i] - maxv);  /* 减最大值防溢出 */
        sum += x[i];
    }
    for (i = 0; i < n; i++) x[i] /= sum;
}
```

## 7. USB ECM 双机通信详解

### 7.1 功能实现原理

**核心功能**：通过 USB ECM 虚拟网卡在 T536 主机与 RK3576 算力模组之间建立 TCP/IP 通信通道，实现 AI 推理 RPC 调用。

**设计思路**：
1. **传输层**（`comm/usb_ecm.c`）：封装跨平台 TCP socket，对上层提供统一的收发接口。
2. **RPC 客户端**（`ai/ai_rpc.c`）：主机侧，组装 JSON 请求，发送特征向量，解析 AI 推理结果。
3. **仿真器**（`sim/compute_module_sim.c`）：无真实 RK3576 时，以本机 TCP 服务线程模拟算力模组行为。
4. **降级机制**：算力模组不可达时，主机自动 fallback 到本地 Stub 推理，保证仿真不中断。

**通信协议**：

请求（主机 → 算力模组）：
```json
{
  "cmd": "infer",
  "features": [0.1234, 0.5678, ..., 0.9012],
  "vthd": 5.230,
  "ithd": 16.400
}
```

应答（算力模组 → 主机）：
```json
{
  "if": 0.6543,
  "ae": 12345.6789,
  "cls": 3,
  "conf": 0.8521,
  "lat": 1
}
```

**工作流程**：
```
主机 T536:
  ai_rpc_infer(feat, metrics, &result)
    → build_request()           组装 JSON
    → usb_ecm_request()        发送 + 等待应答
        → usb_ecm_send()       TCP send
        → usb_ecm_recv()       TCP recv (timeout 2000ms)
    → parse_response()         解析 JSON
    → result.module_available = 1

算力模组 RK3576:
  compute_module_sim 接收连接
    → recv() 读取请求
    → handle_infer():
        → parse_infer_request()  解析特征向量
        → iforest_score()        iForest 推理
        → ae_anomaly_score()     AE 推理
        → cnn1d_classify()       CNN 推理
        → build_infer_response() 组装应答
    → send() 返回 JSON
```

### 7.2 算法说明

**USB ECM 地址分配**：

| 角色 | IP 地址 | 说明 |
|------|---------|------|
| T536 主机 | 192.168.100.x | USB ECM 虚拟网卡（DHCP 分配） |
| RK3576 算力模组 | 192.168.100.1 | USB ECM 虚拟网卡静态 IP |

- 请求超时：2000ms（`AI_RPC_TIMEOUT_MS`）
- 超时处理：标记算力模组离线，调用本地 `local_infer()` fallback。
- 重连机制：下次请求时自动尝试 `usb_ecm_connect()`。

**关键代码片段**（请求-应答式通信）：

```c
int usb_ecm_request(usb_ecm_t *ecm, const char *req,
                    char *resp, int resp_size, int timeout_ms)
{
    int ret;
    /* 确保连接 */
    if (!ecm->connected) {
        if (usb_ecm_connect(ecm) != 0) return -1;
    }
    /* 发送请求 */
    ret = usb_ecm_send(ecm, req, (int)strlen(req));
    if (ret <= 0) return -1;
    /* 接收应答 */
    ret = usb_ecm_recv(ecm, resp, resp_size, timeout_ms);
    if (ret <= 0) return -1;
    return 0;
}
```

**关键代码片段**（带 fallback 的推理调用）：

```c
int ai_rpc_infer(const feature_vector_t *feat,
                 const pq_metrics_t *metrics,
                 ai_result_t *result)
{
    char request[USB_ECM_MAX_PACKET];
    char response[512];
    int  ret;

    /* 构建请求 */
    if (build_request(request, sizeof(request), feat, metrics) != 0) {
        local_infer(feat, result);  /* fallback */
        return 0;
    }

    /* USB ECM 请求-应答 */
    ret = usb_ecm_request(&g_ecm, request, response,
                          sizeof(response), AI_RPC_TIMEOUT_MS);

    if (ret == 0) {
        parse_response(response, result);
        result->module_available = 1;  /* 算力模组在线 */
        if (!g_module_online) {
            PQ_LOGI("ai_rpc: compute module ONLINE (RK3576 via USB ECM)");
            g_module_online = 1;
        }
    } else {
        /* 算力模组不可达，降级为本地推理 */
        if (g_module_online) {
            PQ_LOGW("ai_rpc: compute module offline, fallback to local stub");
            g_module_online = 0;
        }
        usb_ecm_disconnect(&g_ecm);
        local_infer(feat, result);
    }
    return 0;
}
```

#### 7.4.3 算力模组仿真器（sim/compute_module_sim.c）

**核心函数**：

```c
int compute_module_sim_start(const char *listen_ip, int port);
void compute_module_sim_stop(void);
int compute_module_sim_running(void);
```

**关键代码片段**（TCP 服务主循环）：

```c
static void *server_thread_main(void *arg)
{
    socket_t listen_fd = (socket_t)(intptr_t)arg;
    socket_t client_fd;
    char buf[USB_ECM_MAX_PACKET];
    int n;

    while (g_running) {
        client_fd = accept(listen_fd, NULL, NULL);
        if (client_fd == SOCK_INVALID) continue;

        /* 处理该连接的所有请求 */
        while (g_running) {
            n = (int)recv(client_fd, buf, sizeof(buf) - 1, 0);
            if (n <= 0) break;
            buf[n] = '\0';
            handle_infer(client_fd, buf);  /* 运行 AI 推理并返回 */
        }
        SOCK_CLOSE(client_fd);
    }
    return NULL;
}
```

**关键代码片段**（推理处理）：

```c
static void handle_infer(socket_t client_fd, const char *request)
{
    float features[IF_N_FEATURES];
    float if_score, ae_score;
    float probs[CNN_MAX_CLASSES];
    float cnn_conf = 0.0f;
    int   cnn_class = 0;
    char  response[512];

    /* 解析请求 */
    if (parse_infer_request(request, features, IF_N_FEATURES,
                            &vthd, &ithd) != 0) {
        send(client_fd, "{\"error\":\"bad request\"}", 23, 0);
        return;
    }

    /* 模拟 NPU 推理耗时 1ms */
    struct timespec ts = {0, 1000000};  /* 1ms = 1e6 ns */
    nanosleep(&ts, NULL);

    /* 三类 AI 模型推理 */
    if_score = iforest_score(&g_if_model, features);
    ae_score = ae_anomaly_score(features);
    cnn1d_classify(features, 1, IF_N_FEATURES, 1, probs);
    cnn_class = cnn1d_get_class(probs, 7, &cnn_conf);

    /* 返回 JSON 应答 */
    build_infer_response(response, sizeof(response),
                         if_score, ae_score, cnn_class, cnn_conf, 1);
    send(client_fd, response, (int)strlen(response), 0);
}
```

### 9.3 平台抽象原则

**核心原则**：业务代码（`core/`, `ai/`, `comm/`）不得直接调用平台 API。

| 平台相关操作 | 应调用 | 实现位置 |
|--------------|--------|----------|
| 延时 | `hal_sleep_ms()` | `sim/hal_sim.c` |
| 临界区 | `hal_critical_enter/exit()` | `sim/hal_sim.c` |
| 时间戳 | `hal_ht7627s_get_time_us()` | HAL 层 |
| TCP socket | `usb_ecm_*()` | `comm/usb_ecm.c` |
| 线程 | `compute_module_sim_*()` | `sim/compute_module_sim.c` |

### 9.4 浮点运算注意事项

- 所有浮点常量显式加 `f` 后缀：
  ```c
  float x = 3.14159265f;   /* 正确 */
  float y = 3.14159265;    /* 错误：隐含 double */
  ```
- 比较浮点数使用容差：
  ```c
  #define EPSILON 1e-6f
  if (fabsf(a - b) < EPSILON) { /* 相等 */ }
  ```
- 使用 `fabsf`、`sqrtf`、`sinf` 等单精度版本，避免 double 转换开销。

### 9.5 内存管理

- **禁止在核心算法中使用动态内存分配**（`malloc` / `free`）。
- 所有缓冲区使用静态数组或调用方传入的栈内存。
- 栈空间敏感环境下，大数组使用 `static` 修饰或移至全局区。
- AI 模型权重数组使用 `static` 全局变量，避免重复初始化。

## 10. 常见问题与解决方案

### 10.1 编译问题

#### Q1: `gcc: command not found`

```bash
sudo apt update && sudo apt install -y build-essential
```

#### Q2: `implicit declaration of function 'poll'`

**原因**：GCC 15 下 `-std=c99` 与 `_POSIX_C_SOURCE` 宏冲突。

**解决**：已修复，`sim/hal_sim.c` 中已改用 `poll(NULL, 0, ms)` 并包含 `<poll.h>`。

#### Q3: `pthread_mutex_t` 未声明

**原因**：未包含 `<pthread.h>` 或 Makefile 未链接 `libpthread`。

**解决**：已修复，Makefile 在 Linux 分支自动链接 `-lpthread`，`hal_sim.c` 已包含 `<pthread.h>`。

#### Q4: `nanosleep` 隐式声明

**原因**：`nanosleep` 需要 `_POSIX_C_SOURCE` 宏。

**解决**：已修复，`compute_module_sim.c` 顶部添加 `#define _POSIX_C_SOURCE 200112L`。

#### Q5: Windows 下 `pq_sim.exe` 提示缺少 `libgcc_s_seh-1.dll`

**原因**：MinGW 运行时 DLL 不在 PATH 中。

**解决**：将 `C:\msys64\mingw64\bin` 加入系统 PATH，或将所需 DLL 复制到 exe 同级目录。

### 10.2 运行问题

#### Q6: 场景运行结果与预期不符

**排查步骤**：
1. 检查 `config.ini` 中的阈值是否被意外修改。
2. 在 `core/scenario_detect.c` 中添加 `PQ_LOGI` 打印中间判定值。
3. 对比 `sim/hal_sim.c` 中的场景参数表是否与预期一致。

#### Q7: AI 模组显示 OFFLINE

**排查步骤**：
1. 检查 `config.ini` 的 `[compute_module]` 段，`enabled` 是否为 1。
2. 检查端口 9090 是否被占用：`netstat -tlnp | grep 9090`。
3. 检查防火墙是否阻止本地回环连接。
4. 查看日志是否有 `compute_module_sim: bind() failed` 错误。

#### Q8: MATLAB 与 C 仿真结果数值不一致

**原因**：两套仿真参数基准不同（MATLAB 为 400kVA 居民台区，C 为 800kVA 工业台区）。

**解决方案**：统一参数基准。修改 `loadSystemParams.m` 或 `config.ini` 使两者一致。

### 10.3 跨平台问题

#### Q9: Windows 下 socket 类型不匹配

**原因**：Windows `SOCKET` 为 `void*`，Linux 为 `int`。

**解决**：已修复，`usb_ecm_t.sock` 使用 `intptr_t` 统一类型。

#### Q10: Linux 下 `struct timeval` 未声明

**解决**：已在 `usb_ecm.c` 中添加 `#include <sys/time.h>`。

### 10.4 交叉编译与真实硬件问题（v2.2.0 新增）

#### Q11: `aarch64-linux-gnu-gcc: command not found`

**原因**：交叉编译器未加入 PATH。

**解决**：使用完整路径或在脚本中指定：
```bash

# 或
/opt/toolchain/gcc-linaro-11.3.1-2022.06-x86_64_aarch64-linux-gnu/bin/aarch64-linux-gnu-gcc --version
```

#### Q12: 交叉编译后 `file` 命令显示错误架构

**排查**：
```bash

# 预期: ELF 64-bit LSB executable, ARM aarch64
# 如显示 x86-64 说明误用了宿主机 GCC
```

**解决**：确保使用 `CROSS_CC` 指定 aarch64 编译器。

#### Q13: T536 上运行 `pq_terminal_arm` 提示 `No such file or directory`

**排查**：

#### Q14: T536 连接 RK3576 时 `connect: Connection refused`

## 11. 维护更新指南

### 11.1 如何添加新仿真场景（S6）

**步骤 1**：在 `sim/hal_sim.c` 的场景参数表中添加新条目。

**步骤 2**：在 `sim/hal_sim.h` 添加场景宏：`#define SCEN_S6  0x5336`。

**步骤 3**：在 `core/scenario_detect.h` 扩展枚举：`SCENARIO_S6_NEW = 6`。

**步骤 4**：在 `core/scenario_detect.c` 中添加判定规则、场景名称、治理建议。

**步骤 5**：在 `sim/sim_main.c` 的命令行解析中增加 `"S6"` 选项支持。

**步骤 6**（MATLAB 侧）：在 `runSimulation.m` 的 `configureScenarioPower` 函数中添加 S6 分支。

### 11.2 如何替换 AI Stub 为真实模型

**孤立森林**：
1. 使用 scikit-learn 训练 iForest 模型。
2. 导出树结构为 C 数组（JSON 或二进制）。
3. 实现 `iforest_load_model()` 从文件加载真实模型。

**自编码器**：
1. 使用 PyTorch 训练 AE 模型。
2. 量化权重至 INT8（可选，提升推理速度）。
3. 替换 `ae_init()` 中的权重数组为真实值。

**1D-CNN**：
1. 使用 PyTorch/TensorFlow 训练 ONNX 模型。
2. 通过 RK3576 NPU SDK 转换为 `.nb` 格式。
3. 替换 `cnn1d_infer.c` 为 NPU 推理 API 调用。
